# Fishing-bot для OctoWoW / Vanilla WoW 1.12.1

Личная резервная копия рабочего рыболовного бота для Windows. Инструкция рассчитана на восстановление на другом компьютере: установка Python, подготовка клиента, макросов, автолута, очистки сумок и калибровка поиска/звука.

Снимок подготовлен 14 октября 2026 года. Рабочая папка на исходном ноутбуке была `C:\Users\user\Downloads\Fishing-bot`, клиент — `C:\Users\user\Downloads\OctoWow`. **Эти пути не зашиты в бота:** папку со скриптами можно разместить в другом месте. Скрипт ищет активное окно по заголовку, а эталон и журналы — рядом с самим собой.

## 1. Быстрое восстановление

1. Скачайте репозиторий из своего приватного GitLab, например в `C:\Fishing-bot`. Не используйте старую `.venv`, перенесённую с другого компьютера.
2. Установите **Python 3.11 x64 с Python Launcher**. Проверьте `py -3.11 --version`.
3. Запустите `setup.cmd`, дождитесь сообщения `Ready. Run start.cmd`.
4. Распакуйте `addons-and-macros.zip` в отдельную временную папку. При закрытой игре перенесите содержимое `Interface\AddOns` в клиент, а `Sound` — в корень клиента, как описано ниже. Существующие файлы предварительно сохраните.
5. Обеспечьте загрузку SuperWoW и SuperAPI: они дают используемые здесь автолут и лимит макросов 511 символов. DLL SuperWoW скачивается из официального проекта отдельно; её нет в архиве.
6. Включите постоянный автолут. Наденьте удочку. Настройте кнопки: **1 — Fishing; 2 — макрос наживки; 3 — макрос контейнеров**. Проверьте каждую вручную.
7. Убедитесь, что звук игры выходит на устройство Windows по умолчанию. Уберите музыку и фоновые звуки; эффекты оставьте включёнными. Проверьте трёхтональный звук клёва.
8. Проверьте длительность вашей наживки на удочке. В снимке бота интервал **600 секунд**; если улучшение действует 5 минут, перед длительным запуском измените `lure_interval=600` на `lure_interval=300` в определении `run_cycles`.
9. При необходимости настройте SimpleAutoDelete: сначала `/sad off`, затем добавление конкретных предметов, `/sad list`, `/sad test`, и только после проверки `/sad on`.
10. Зайдите персонажем к воде. Запустите `start.cmd`, введите `2` минуты для первого испытания. Во время отсчёта переключитесь в игру и оставьте курсор неподвижно над пустой водой.

**Окончание введённого времени закрывает исходное окно игры. F8/Esc и остановка после десяти неудачных поисков игру не закрывают.**

## 3. Установка Python и запуск

Испытанное окружение: Windows 10 x64, Python **3.11.9 x64**. Для Windows 11 требуется собственное испытание ввода и аудиоустройства. Python другой основной версии не считается проверенным окружением этого снимка.

Официальная загрузка: [Python для Windows](https://www.python.org/downloads/windows/). В установщике нужны Python Launcher и 64-разрядная установка. Альтернативная установка через PowerShell:

```powershell
winget install --exact --id Python.Python.3.11 --source winget --architecture x64
```

После установки закройте и заново откройте терминал:

```powershell
py -3.11 --version
```

Из папки репозитория выполните:

```powershell
Set-Location -LiteralPath 'C:\Fishing-bot'
.\setup.cmd
.\.venv\Scripts\python.exe -m pip check
```

Версии из `requirements.txt`: `numpy==2.4.6`, `keyboard==0.13.5`, `SoundCard==0.4.6`, `cffi==2.1.1`. Не обновляйте их все одновременно при восстановлении. Если когда-нибудь пакет перестанет скачиваться, меняйте версии осознанно и повторяйте проверку звука и остановки.

Если `py` отсутствует, используйте полный путь к установленному Python 3.11:

```powershell
& 'C:\путь\к\Python311\python.exe' -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements.txt
```

Запуск без дополнительных настроек:

```powershell
Set-Location -LiteralPath 'C:\Fishing-bot'
.\start.cmd
```

Либо двойной клик по `start.cmd`. Файл сам переходит в свою папку. Длительность вводится в минутах, допускается дробное число и десятичная запятая. Время работы начинает отсчитываться **после 10-секундного отсчёта и проверки стартового курсора**, до первоначального применения наживки.

Для просмотра параметров без запуска рыбалки:

```powershell
.\.venv\Scripts\python.exe .\cursor_test.py --help
```

## 4. Подготовка клиента, аддоны и зависимости

Бот рассчитан на клиент **Vanilla 1.12.1**, конкретно на использовавшуюся сборку OctoWoW. Современный WoW Classic — другой клиент с другим API; аддоны для Classic 1.13/1.15 не являются заменой аддонов 1.12.

### 4.1. SimpleAutoDelete: выборочное удаление улова

Источник: [fondlez/SimpleAutoDelete](https://github.com/fondlez/SimpleAutoDelete). В архиве лежит **локальная адаптация**, а не нетронутый upstream. Заменять её свежей загрузкой без сверки изменений нельзя. В папке аддона сохранены исходная лицензия, ссылка/commit и `LOCAL-CHANGES.txt`.

Скопируйте папку так, чтобы получилось:

```text
<клиент>\Interface\AddOns\SimpleAutoDelete\SimpleAutoDelete.toc
```

Без дополнительного уровня `SimpleAutoDelete\SimpleAutoDelete` и без суффикса `-main`/`-master`. У `.toc` указано `Interface: 11200`. Полностью перезапустите клиент и включите аддон в меню AddOns.

Поведение адаптации:

- события `BAG_UPDATE` объединяются с задержкой 0,4 секунды;
- проверка после `LOOT_CLOSED` сохраняется;
- при бое, открытой добыче, занятом курсоре/выборе цели или блокировке слота удаление откладывается;
- после устранения препятствия проверка повторяется;
- собственные удаления не вызывают повторного входа в очистку;
- удаляется **вся стопка** только по явно добавленному item ID;
- нет правил по качеству, цвету, цене или частичному совпадению названия;
- настройки сохраняются **отдельно для каждого персонажа**;
- при первом запуске список пуст и автоочистка выключена.

Команды:

| Команда | Действие |
|---|---|
| `/sad add <ссылка или ID>` | Добавить точное правило |
| `/sad add <название>` | Найти точное, однозначное название среди предметов в сумках и сохранить ID |
| `/sad remove <ссылка, ID или название>` | Удалить правило |
| `/sad list` | Показать список |
| `/sad test` | Только показать предполагаемое удаление |
| `/sad on` / `/sad off` | Включить / выключить автоматическую очистку |
| `/sad toggle` / `/sad status` | Переключить / показать состояние |
| `/sad run` | Запросить одно **реальное** удаление даже при выключенной автоочистке |
| `/sad delay 0.4` | Задержка объединения событий, допустимо 0.1–5 с |
| `/sad print true` / `false` | Сообщения об удалённых стопках |

`/sad off` также отменяет ожидающее ручное `/sad run`. Старый список по названиям при миграции сохраняется отдельно, но не активируется автоматически.

Добавление ссылки: напишите `/sad add ` с пробелом, **Shift-кликните предмет в сумке**, затем Enter. До окончания настройки оставьте `/sad off`. После `/sad list` выполните `/sad test`, убедитесь, что показаны только ненужные стопки, затем `/sad on`. Не включайте очистку для рыбы, которую собираетесь готовить или продавать.

Прежний личный список, только как набор команд для ручного выбора:

```text
/sad add Raw Sunscale Salmon
/sad add Raw Whitescale Salmon
/sad add Raw Spotted Yellowtail
/sad add Raw Rockscale Cod
/sad add Raw Redgill
/sad add Raw Glossy Mightfish
/sad add Firefin Snapper
```

Добавление **по названию** работает, когда соответствующий предмет находится в сумках. Ссылка или ID не требуют поиска по названию. Этот список не активирован и не зашит в аддон из архива.

### 4.2. SuperAPI + SuperWoW: макросы 511 символов и автолут

- [SuperAPI](https://github.com/balakethelock/SuperAPI) — аддон; копия с ноутбука включена в архив.
- [SuperWoW](https://github.com/balakethelock/SuperWoW) — мод клиента; [официальный релиз](https://github.com/balakethelock/SuperWoW/releases/tag/Release).

Установленный SuperAPI требует `SUPERWOW_VERSION >= 2.2`. Он увеличивает поле редактора макросов до **511 символов**. Это важно: используемые ниже длинные макросы не рассчитаны на стандартный лимит 255. Не считайте лимит 511 свойством чистого Vanilla.

Скопируйте SuperAPI из архива в `Interface\AddOns\SuperAPI`. Если SuperWoW уже входит в сборку, используйте существующий механизм его загрузки и проверьте сообщение SuperAPI в чате. Не добавляйте второй загрузчик поверх работающего без необходимости.

Для клиента без SuperWoW официальный способ: скачать мод, положить `SuperWoWhook.dll` и `SuperWoWlauncher.exe` рядом с `WoW.exe` и запускать игру через этот launcher. Подробности и совместимость смотрите в README проекта. **DLL/launcher не включены в пакет:** лицензия SuperWoW ограничивает распространение, поэтому скачивайте их у автора.

На исходном ноутбуке DLL грузилась через существующий загрузчик сборки и запись `SuperWoWhook.dll` в `dlls.txt`; обычный запуск `WoW.exe` может не загрузить мод. Используйте launcher OctoWoW/существующий настроенный загрузчик либо официальный launcher SuperWoW. Не заменяйте целиком чужой `dlls.txt` минимальным примером — там могут быть другие нужные моды.

В SuperAPI откройте настройки **правой кнопкой по его значку миникарты** и выберите Autoloot → **Always on**. После перезапуска перепроверьте это. По умолчанию копия SuperAPI предлагает Shift-режим, а бот Shift не удерживает. Если клиент пропатчен Vanilla Tweaks quickloot, режимы могут быть инвертированы: проверяйте фактический сбор добычи, а не только надпись в настройке.

Признаки правильной настройки: один правый клик забирает весь улов; один клик по макросу контейнера забирает содержимое и закрывает окно; редактор макроса показывает лимит 511.

Другой проверенный способ постоянного автолута тоже допустим. Одновременно включать несколько конкурирующих механизмов автолута не требуется. Бот сам предметы из окна добычи не перебирает.

### 4.3. Звуковой сигнал клёва: файл, а не отдельный FishPing-аддон

В используемом клиенте не найден отдельный аддон FishPing. Это название нашего **трёхтонального сигнала**. Он установлен заменой звука:

```text
<клиент>\Sound\Spells\Tradeskills\FishBite.wav
```

При закрытой игре сохраните предыдущий файл, если он есть, и скопируйте `Sound` из архива в корень клиента. WAV рядом с ботом оставьте под именем `FishBite-reference.wav`.

Сигнал: 1100 → 1750 → 1350 Гц. Снимок эталона: PCM16, моно, 22050 Гц, примерно 0,49 с. Детектор переводит его к 24000 Гц и сравнивает временной рисунок энергии в трёх частотных полосах.

Проверьте при ручной рыбалке, что **во время клёва** действительно звучит эта последовательность. Если сборка игнорирует свободный файл или воспроизводит другой звук, установка файла сама по себе недостаточна. Сначала устраните это в клиенте; понижение порога детектора не заменит отсутствующий сигнал.

### 4.4. Что не является зависимостью рыбалки

- [OctoLogin](https://github.com/fmustafayaman/OctoLogin) — отдельный DLL-мод подключения OctoWoW. На ноутбуке был установлен и прописан в загрузчике, но бот не вызывает его API. При восстановлении устанавливается по инструкции официального проекта, отдельно.
- [Turtle AutoLogin](https://github.com/Haaxor1689/turtle-autologin) — необязательный Patch-Y.mpq для сохранения данных входа. Не нужен рыбалке; совместимость с OctoWoW отдельно требует проверки. Config.wtf с паролем никогда не кладите в репозиторий.
- [ShaguTweaks](https://github.com/shagu/ShaguTweaks) и [pfUI](https://github.com/shagu/pfUI) — интерфейсные аддоны исходного клиента, но прямых обращений к ним в боте нет. Они не включены в этот минимальный пакет.

В пакете нет серверных настроек или данных для входа. Если клиент требует дополнительные моды, их восстанавливают отдельно от фишбота.

## 5. Кнопки и макросы

Все три действия должны срабатывать от обычных верхних клавиш **1, 2, 3**, без Shift/Ctrl/Alt и без NumPad. Персонаж должен находиться вне боя, с надетой удочкой и закрытой строкой чата. Названия предметов в этих макросах английские; для другой локализации замените их на названия своего клиента. Проверка не зависит от регистра.

**1 — Fishing.** Перетащите заклинание Fishing из книги на привязанную к 1 кнопку. Отдельный макрос для заброса не нужен.

**2 — только Aquadynamic Fish Attractor, из любой сумки:**

```lua
/script for b=0,4 do for s=1,GetContainerNumSlots(b) do local l=strlower(GetContainerItemLink(b,s) or "");if strfind(l,"aquadynamic fish attractor",1,true) then UseContainerItem(b,s);if SpellIsTargeting() then PickupInventoryItem(16);ReplaceEnchant();end return end end end
```

Удочка должна быть **надета в основной руке**, а не просто лежать в сумке. Макрос ищет первый стак подходящей наживки в сумках 0–4 и использует его. При следующем нажатии после исчерпания стака найдёт следующий. `SpellIsTargeting()` защищает от попытки снять удочку, если наживки нет. `ReplaceEnchant()` подтверждает замену действующего временного улучшения.

Макрос не проверяет остаток длительности и не применяет другие наживки. В боте нет обратной связи о том, удалось ли наложить улучшение: запас наживки и успех первого нажатия проверяются вручную.

**3 — четыре вида контейнеров, один за нажатие:**

```lua
/script for b=0,4 do for s=1,GetContainerNumSlots(b) do local l=strlower(GetContainerItemLink(b,s) or "");if strfind(l,"bloated mightfish",1,true) or strfind(l,"big-mouth clam",1,true) or strfind(l,"mithril bound trunk",1,true) or strfind(l,"heavy crate",1,true) then UseContainerItem(b,s);return end end end
```

Контейнеры: Bloated Mightfish, Big-mouth Clam, Mithril Bound Trunk, Heavy Crate. Поиск буквальный (`1,true`): дефис не является оператором Lua-шаблона. Это исправляет прежнюю ошибку с Big-mouth Clam.

Мы сохранили последний вариант **по названиям**: предложенный ранее вариант по ID в игровом испытании не сработал. Макрос открывает только один контейнер, а бот нажимает 3 один раз после успешного улова. Ранее накопившийся запас нужно открыть несколькими нажатиями вручную. При отсутствии контейнеров макрос ничего не делает. Автолут должен работать без Shift.

Создавайте макросы вручную из текстовых файлов; не переносите весь личный `macros-cache.txt`. Положите макросы на соответствующие кнопки панели и проверьте именно клавиатурой. Если редактор обрезает строку, сначала восстановите лимит 511 через SuperAPI/SuperWoW.

## 6. Как работает бот

1. Запрашивает минуты; отсчитывает 10 секунд.
2. Находит окно с заголовком `World of Warcraft`, проверяет фокус и считывает исходный системный курсор над пустой водой. Запоминает позицию, границы окна и PID исходного окна игры.
3. Запускает общий таймер. Перед первым забросом нажимает 2 и ждёт 5,5 с.
4. Возвращает мышь в исходную позицию; нажимает 1; ждёт 2 с.
5. Идёт по сетке клиентской области с шагом 60 пикселей. Точки упорядочены от `(50% ширины, 40% высоты)` наружу, а не строго от геометрического центра экрана. После движения ждёт 40 мс.
6. Сравнивает форму и hotspot системного курсора с начальной рукой. Обнаруженное изменение перепроверяет спустя 20 мс, оставаясь на этой точке. Важно: код распознаёт **любую устойчивую смену формы**, а не отдельный заранее известный рисунок шестерёнки.
7. Если поплавок не найден за 5 с, выполняет новый заброс. После 10 таких поисков подряд останавливается. Найденный поплавок сбрасывает счётчик даже при последующем отсутствии звука.
8. После нахождения включает свежий loopback-рекордер устройства вывода Windows по умолчанию и ждёт трёхтональный сигнал.
9. Общий срок от заброса до решения о клике — 30 с. При распознанном сигнале выполняет правый клик; иначе повторяет заброс.
10. После клика ждёт 1 с для улова, нажимает 3 и ждёт ещё 1 с. Эти паузы обработки добычи идут **после** завершённой рыболовной итерации и могут увеличить время между забросами сверх 30 с.
11. Перед очередным забросом, если со времени последнего нажатия 2 прошло не менее 600 с, обновляет наживку. Это выполняется между итерациями, поэтому нажатие может быть чуть позже ровных десяти минут.

Бот использует общую мышь/клавиатуру и требует активную игру. Размер клиентской области считывается при старте, а не каждый цикл: **после изменения разрешения, размера или положения окна остановите и перезапустите бот**.

Фокус проверяется перед вводом и во время поиска/прослушивания. При его потере бот прекращает работу с ошибкой. Он не подключается заново, не выбирает персонажа и не доказывает, что причиной серии промахов был именно дисконнект.

## 7. Разрешение, FPS и калибровка поиска

Рабочие настройки ноутбука: 1920×1080, примерно 55 FPS, `step=60`, `settle-ms=40`, `timeout=5`. На основном ПК FPS был существенно выше. Эти значения — отправная точка, не универсальная гарантия.

Границы окна определяются автоматически. Жёсткой привязки к 1920×1080 нет, но сетка остаётся в **пикселях**. Больше разрешение → больше точек; мелкий/далёкий поплавок → меньше область наведения, в которую сетка может вообще не попасть.

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `--step` | 60 | Шаг сетки в пикселях |
| `--settle-ms` | 40 | Ожидание обновления курсора после движения |
| `--timeout` | 5 | Лимит поиска после паузы появления поплавка |
| `--cast-delay` | 2 | Пауза после заброса |
| `--recast-delay` | 1 | Пауза после успешного клика перед кнопкой 3 |
| `--audio-score` | 0.82 | Порог сходства звука |
| `--audio-min-rms` | 0.0001 | Минимальный уровень сигнала |
| `--window-title` | `World of Warcraft` | Точный заголовок игрового окна |

Пример пробного запуска с более плотной сеткой:

```powershell
.\start.cmd --step 40 --settle-ms 40 --timeout 5
```

Пример более длительного поиска для большого окна:

```powershell
.\start.cmd --step 60 --settle-ms 40 --timeout 8
```

Изменяйте **один параметр за испытание** и сравнивайте `found`, `missed`, `search_elapsed` и количество проверенных точек в журнале.

- Если на глаз курсор меняется, но бот уходит дальше: попробуйте `--settle-ms 50` или `60`. Слишком короткое ожидание при низком FPS читает старую форму курсора.
- Если особенно часто пропускается далёкий мелкий поплавок: попробуйте шаг 40 или 30. Увеличение ожидания не помогает, если точка сетки не попала в область наведения.
- Меньший шаг и большее ожидание уменьшают площадь, которую бот успевает проверить за 5 с. Увеличивайте timeout только если действительно хотите искать дольше, а не быстрее перезабрасывать.
- При 1920×1080 и шаге 60 сетка содержит 576 точек. Одни паузы 40 мс потребовали бы около 23 с на весь обход. **За 5 с проверяется только начальная часть сетки**, это сознательная ставка на новые забросы.
- Снижение разрешения иногда повышает FPS, но может уменьшить поплавок в пикселях. Не рассчитывайте на него как на автоматическое исправление.
- Уберите из зоны поиска панели, подсказки и объекты с другим курсором: бот считает изменением не только шестерёнку.
- Если Windows сообщает скрытый курсор, клиент может рисовать программный курсор. Проверьте доступную в сборке настройку аппаратного курсора; бот читает именно системную форму, а не изображение на экране.

Число точек примерно равно `ширина × высота / step²`. Доступное число проверок примерно `timeout / (settle-ms / 1000)` и ещё меньше с учётом вызовов Windows и подтверждения.

Подтверждение формы (`0.020`) находится внутри `scan`, отдельного параметра запуска для него нет. Сначала настраивайте ожидание и шаг, а не удаляйте подтверждение: оно защищает от запоздалой смены курсора с предыдущей точки.

## 8. Калибровка аудио

Loopback захватывает звук **устройства вывода по умолчанию**, а не микрофон. В Windows выберите нужные динамики/наушники и проверьте, что приложение WoW не перенаправлено на другое устройство в микшере. При смене наушников/HDMI/Bluetooth перепроверьте маршрутизацию и перезапустите бот.

Звуковые эффекты должны быть слышимы; музыку и фон лучше выключить. Постороннее аудио с того же устройства тоже попадает в захват. При первом тесте не воспроизводите эталон поверх работающего бота: он может принять его за настоящий клёв.

В консоли и `audio-matches.jsonl` есть:

- `score` — сходство с эталоном, порог 0.82;
- `coverage` — энергия ожидаемых тонов, внутренний порог 0.25;
- `rms` — уровень, порог 0.0001;
- `matched` — выполнены все условия распознавания.

Если поплавок найден, но доходит до `bite_timeout`, сначала проверьте реальный звук, устройство и громкость. Только потом экспериментируйте, например:

```powershell
.\start.cmd --audio-score 0.80
```

Снижение порога повышает риск ложного клика; проверяйте и успешные поклёвки, и интервалы без клёва. Если `rms` ниже порога, сначала увеличьте уровень эффектов или проверьте маршрут. `--audio-min-rms` меняйте после этого. `coverage` не регулируется командной строкой.

Если заменяете сигнал, одновременно обновляйте **оба** WAV и частотные полосы в `audio_detector.py`, если поменялись сами частоты. Простая замена эталона случайным звуком не делает этот детектор универсальным.

## 9. Настройки, которые пока меняются только в коде

Редактируйте при остановленном боте; сохраните копию файла и после изменения выполните короткое испытание.

| Где в `cursor_test.py` | Текущее значение | Что менять при необходимости |
|---|---:|---|
| Определение `run_cycles`: `lure_interval` | 600 с | Интервал нажатия 2; согласовать с длительностью наживки |
| Определение `run_cycles`: `lure_delay` | 5.5 с | Пауза на применение; не короче фактического применения |
| Вызов `run_cycles` из `main`: `iteration_seconds` | 30 с | Полный лимит рыболовной части итерации |
| Условие `consecutive_misses>=10` | 10 | Порог досрочной остановки; при изменении также обновить текст сообщений и итоговый отчёт |
| `scan`: дополнительное ожидание `0.020` | 20 мс | Подтверждение устойчивой смены курсора |
| После `api.open_container()`: `stop.wait(1.0)` | 1 с | Пауза для контейнера после кнопки 3 |
| `Windows.cast/apply_lure/open_container` | 1/2/3 | Виртуальная клавиша и scan code; проще сохранить эти привязки в игре |

**Наживка:** прежняя Bright Baubles и нынешняя Aquadynamic Fish Attractor не обязательно имеют одну длительность. В стандартном Vanilla Aquadynamic обычно действует 5 минут; серверные сборки могут менять это. На своей удочке проверьте фактическую длительность. При пяти минутах замените `lure_interval=600` на `lure_interval=300`. При десяти минутах оставьте 600. Макрос работает с обоими интервалами, но бот сам длительность улучшения не считывает.

Статические строки приветствия показывают исходные настройки и не все отражают переданные CLI-параметры. Для проверки действующих значений смотрите команду запуска, аргументы parser и журнал. В частности, отдельная функция `scan` имеет исторический default timeout=25, но нормальный запуск явно передаёт в неё **5 с** из parser/run_cycles.

## 10. Первый контрольный запуск

1. Проверьте вручную кнопки 1, 2, 3. Убедитесь, что 3 действительно открывает контейнер при его наличии, и автолут забирает всё.
2. Проверьте SimpleAutoDelete без удаления: `/sad off`, `/sad list`, `/sad test`. На новом персонаже настройки независимые.
3. Поставьте персонажа к пустой воде и закройте все лишние окна. Оставьте запас наживки и место под содержимое контейнеров.
4. Запустите бот на 2 минуты. Во время отсчёта переключитесь в игру, оставьте мышь над пустой водой. Начальная форма должна быть рукой, а не шестерёнкой/другим объектом.
5. Проследите за первым применением наживки и хотя бы двумя уловами: 1 → поиск → звук → правый клик → 3 → новый заброс.
6. Для проверки ручной остановки нажмите F8: управление прекратится, игра останется открытой. Не используйте Esc как единственный тест, если оно одновременно меняет игровые окна.
7. Отдельным коротким запуском проверьте завершение по времени: оно отправляет исходному окну запрос закрытия, не принудительное уничтожение процесса.
8. Только после этого запускайте длинную сессию. Не запускайте две копии бота одновременно.

## 11. Журналы и устранение проблем

Файлы создаются рядом с ботом:

| Файл | Содержание |
|---|---|
| `last-result.json` | Итог текущего/последнего запуска |
| `cycles.jsonl` | Результаты завершённых итераций, добавляются в конец |
| `audio-matches.jsonl` | Частые оценки аудио, добавляются в конец |

В аудиожурнале сохраняются оценки, не запись WAV. Он растёт быстро: на исходном ноутбуке накопилось более 500 МБ. После остановки можно переместить старые журналы в отдельную папку или удалить ненужные; при следующем запуске они создадутся заново. В GitLab их не добавляйте.

Итоговые результаты:

- `duration_finished` — закончился общий таймер; возможен `game_close: close_requested`;
- `manually_stopped` — F8/Esc/Ctrl+C;
- `consecutive_search_failures` — 10 промахов подряд, игра оставлена открытой;
- `error` — ошибка с описанием/traceback, например потеря фокуса.

| Симптом | Что проверить |
|---|---|
| `py` не найден | Launcher, новый терминал или полный путь Python |
| Ошибка зависимости/импорта | Нужная `.venv`, `requirements.txt`, `pip check` |
| Окно не найдено | Игра запущена, не свёрнута; точный `--window-title` |
| `WoW lost focus` | Игра должна быть активной, не переключайтесь на другие приложения |
| `Windows cursor is hidden` | Аппаратный системный курсор/настройки клиента |
| Много `not_found` | Стартовая рука, шаг, ожидание, зона заброса, фактический размер окна |
| Курсор останавливается на панели | Лишний UI в сетке; устойчивую смену курсора бот считает поплавком |
| Найден, но нет клика | FishBite.wav, маршрутизация звука, `score/coverage/rms` |
| Не применяется наживка | Кнопка 2, надетая удочка, точное имя, запас, применение не прервано |
| Наживка истекает до обновления | Реальная длительность против `lure_interval` |
| Контейнер открывается, но остаётся | Автолут без Shift; время на сбор; свободные слоты |
| Макрос обрезается | SuperWoW загрузился, SuperAPI включён, лимит 511 |
| Сумки не очищаются | `/sad status`, список текущего персонажа, `/sad test`, блокировки |
| Ранняя остановка после 10 промахов | Подключение/позиция персонажа/рыбалка на 1; это не доказательство дисконнекта |

На другом ПК заново проверяются разрешение, масштаб Windows, FPS, системный курсор, название окна и аудиоустройство. Не переносите сырые сохранённые handle курсора или окна: бот получает новые при каждом старте.

## 12. Хранение в приватном GitLab

Создайте пустой **Private** репозиторий. Загрузите содержимое этой папки так, чтобы README и скрипты оказались в корне. Вложенный `addons-and-macros.zip` храните рядом. Не загружайте внешний полный `Fishing-bot-GitLab.zip` внутрь самого репозитория — это только удобный транспортный архив.

`.gitignore` исключает окружение, журналы, игровые настройки и секреты. Всё равно перед загрузкой проверьте состав файлов: не переносите целиком игру или папку `WTF`. В `.venv` нет исходных данных для восстановления, она создаётся через setup.

Снимок основной Python-логики сохранён **без изменений** относительно папки бота на момент упаковки. Локальные изменения SimpleAutoDelete уже включены. Чтобы сохранить свою калибровку, запишите используемую команду запуска в README, а изменения кода фиксируйте отдельным commit.

## 13. Что проверено при сборке пакета

Проверяются целостность архивов и файлов, совпадение Python-исходников со снимком, синтаксис Python, совпадение двух WAV, распознавание эталона без воспроизведения, макросы в изолированной Lua-среде и содержимое `.toc`. Для SimpleAutoDelete сохранена проверка 17 сценариев в имитации API Vanilla на Lua 5.1; это не выполнение в реальном Lua 5.0/WoW.

Игру и бота для сборки пакета не запускали. В новой установке отдельно проверяются загрузка модов, реальные макросы, автолут, аппаратный курсор, поиск поплавка, аудиозахват, применение наживки, очистка сумок и остановки. Совместимость новой версии клиента не следует автоматически из наличия этих файлов.
